# 管理渠道账户分批与历史分页（2026-10-13）

根因：渠道账户一次请求 `ids<=500` 被页面当成一次业务操作上限；翻页清掉选择且操作只取当页记录。关联任务忽略页面参数、只取前200条并把该页长度冒充总数，违反V1与V5。实际验证只调用临时数据库和假API，不调用生产操作或真实渠道。

| 附录A项 | 本次落实与第8章依据 |
|---|---|
| 1 定位 | 既有管理渠道账户的启用/停用/归档/恢复、关联任务查询（5.4，8.1）。 |
| 2 数据 | 账户与任务事实仍在既有SQLite；选择、进度、逐项失败只在管理页面内存，不新增业务字段（8.1）。 |
| 3 命令与事件 | 复用batch action；新增可选partial逐项回执，旧客户端维持整批原子语义。服务端仍授权、审计、通知池刷新（8.2）。 |
| 4 执行 | provider负责有限500项请求窗口串行推进；一次点击执行全部已选ID。不是生成任务，无收费（8.3/8.4）。 |
| 5 幂等与重试 | 目标键为账户ID+状态命令；重复设置已到目标状态返回成功且不改变归档时间。只保留失败/未确认ID，重试只请求这些ID；成功ID不重发（8.2/8.3）。 |
| 6 上游 | 不新增上游请求或能力；HTTP响应失败把当窗及剩余ID列为未完成，明确人工重试（8.5）。 |
| 7 提示词 | 无（8.6）。 |
| 8 配置 | 500为传输窗口，不是业务数量上限，无新用户配置（8.7）。 |
| 9 媒体 | 无媒体或公网地址，历史仍脱敏（8.8）。 |
| 10 界面 | 复用现有AntD表格/提示/确认；跨页保留ID，可分页读取选中全部搜索匹配项。显示成功数/失败数/未完成数与仅未完成重试。后端重新核验当前账户状态，不凭选中行快照做写入判断（8.9/8.10）。 |
| 11 导航搜索 | 保留当前渠道页与搜索；改变搜索清选择；查询全匹配项按pageSize200逐页读，选择过程禁止写操作（8.11）。 |
| 12 制作方式 | 无差异（8.12）。 |
| 13 失败 | partial每项隔离事务，账户不存在/归档冲突脱敏返回code/message；协议不完整不冒称成功；请求失败停止续窗，成功项保留（8.13）。 |
| 14 观测 | 既有审计保留action/ID/成功失败计数，不记录凭据、输入/输出；查询真实COUNT与稳定created_at DESC,id DESC排序分页（8.14）。 |
| 15 恢复环境 | 运行与失败选择保留本页内存；刷新丢失临时进度，账户事实仍在库，可重新选中重复幂等状态命令。无后台自动复活，无付费请求；权限失效停止新窗，SQLite写失败逐项显式失败（8.2b/8.3/8.4b）。 |
| 16 测试 | 临时内存SQLite验证>500组合、partial混合失败/重试不改成功归档时间、旧原子语义；>200关联任务跨页无遗漏总数准确、参数拒绝、脱敏。UI假API验证跨页选择、全匹配>500、失败与仅失败重试/传输失败（8.15）。 |
| 17 不变量 | V1数据库事实/真实总数；V2状态命令自然幂等；V3分批只在provider；V4UI→provider→REST→store；V5每项失败与请求未完成可见。第8章足以覆盖，无新架构规则。 |

范围外：激活期限3650和凭据认证策略、真实清理上游语义、共享包、COS与Miora上传意图、生产执行。凭据容器大小与激活码数量扩展见 `admin-credential-streaming-and-code-windows.md`。清理已选ID通过有限窗口汇总已有检查结果，因旧清理API只返回汇总不承诺逐项重试。
