# AIGate Qwen3-ASR 批量听写

ASR 与 ComfyUI 各自管理节点和作业。热机节点支持上传与推理流水线重叠（同时承接
1 个在途推理和 1 个下一任务上传），且冷节点仅在尚无在途托管节点或排队深度达到
阈值（`SYSTEM_ASR_SCALE_OUT_QUEUE_DEPTH`，默认 3）时才扩容，避免小突发盲目冷启
多余 GPU。任务顺序按创建时间。使用与视频相同的网关鉴权、任务回执和客户端直传模式。
Hailuo 接受清单和听写结果。

- `SYSTEM_ASR_WORKERS` 配置逗号分隔的节点 HTTPS 地址。
  `SYSTEM_ASR_WORKER_KEY` 配置 Hailuo 与节点的内部凭据。
  节点在 `GET /health` 返回 `ready: true` 后可被分配。
- `SYSTEM_ASR_AIGATE_INSTANCE_IDS` 配置逗号分隔的专用 AIGate 实例 ID，
  使用既有 `AIGATE_ACCESS_TOKEN` 管理开关机。只有领取到任务的实例才开机。
  从官方实例信息读取当前 18080 HTTPS 入口。实例进入运行态后配置平台侧低负载
  自动关机兜底并检查模型服务；非 systemd 镜像通过 SSH 和文件锁启动同一份已安装的
  服务，瞬时 SSH 失败按 5 秒短退避重试而非 60 秒锁死。
  队列为空且实例没有在途作业时，保持 30 秒空闲保护窗口（可用
  `SYSTEM_ASR_IDLE_GRACE_MS` 调整），覆盖逐集连续提交的间隔后再发起关机，
  避免批内反复开关机与模型重载。提交回执未知和重启恢复都保持原实例 ID。
  静态 HTTPS 节点继续由外部管理电源。
- `SYSTEM_ASR_AIGATE_TEMPLATES` 接收包含 `id`、`areaName`、`imageId` 和
  `skuNames` 的个人镜像清单。按各区实际在售机型从低成本到高成本配置
  （如 `A10G-24GB` 优先，再回退 `4090-24GB`/`4090D-48GB`/`5090-32GB`），
  既有单机型配置可用 `skuName`。可通过 `instanceId` 登记已准备的实例。
  确认关机后直接释放临时实例；释放与确认期间的新作业等原实例退役，再按同区镜像重建。
  平台明确报告容量不足或单个机型不可用（非余额不足）时尝试清单下一机型或另一可用区。
  尚未发给节点的任务保留原任务号与截止时间。
- `POST /v1/asr/jobs` 以调用方的 `requestKey` 幂等创建。请求包含
  可选 `language`（`Chinese` 或 `Auto`）和 `clips`。每个分镜提供
  `id`、`filename`、`contentType`、`sha256`、`size` 和 `durationMs`。
- 调用方可按作业 ID 或 `GET /v1/asr/jobs/by-request-key/:key` 查回执。
  本地 SQLite 冻结清单、计费秒数、作业 ID、节点地址和上传令牌。
  入队、等待节点和节点实际执行分阶段显示。
- 在 `awaiting_upload` 阶段，调用方用返回的作业级 Bearer 令牌向节点
  `PUT` 各个音频。节点校验字节、SHA-256 和解码时长。
  `POST /v1/asr/jobs/:id/inputs` 保存提交意图，Hailuo 向冻结节点发出
  幂等启动请求。节点返回缺件时恢复上传阶段，使用原节点和令牌。
- 网关只转发元数据。客户端收取 `result.transcripts` 后继续使用既有
  剧本映射和字幕校时。节点服务失败、时长不符按普通任务失败返回。
  网络抖动保留原节点和 ID，提交确认未返回时只重放对原节点的请求。
- 节点准备保留原启动期限。节点可直传后独立计算上传预约，先预留 8 秒
  供客户端取回执和提交确认，再按清单字节数以 384 KiB/s 计算上传时间。
  预约最短 35 秒，已测整集的两批清单分别为 36 秒和 39 秒，最多 10 分钟。
  到期且尚无启动意图才释放槽位。每秒检查听写终态，把文字事务写入
  SQLite 后回收空闲实例。

首轮按同一部剧的整集音轨验收两个区域的节点，从 New API 创建、直传、
确认、收取逐镜文本并检查重复请求回到原 ID。记录逐阶段用时和结果。
